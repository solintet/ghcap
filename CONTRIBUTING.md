# Contributing / 開発への参加

## English

Use `master` as the integration branch. Make changes on a feature branch when possible. Preserve historical behavior for commits, remotes, authentication and Releases; add regression tests before changing safety-critical logic. Implement one responsibility per Rust module even for small files. Write meaningful English and Japanese comments explaining why state or security checks exist; avoid autogenerated filler comments. Run `cargo fmt --all`, `cargo clippy --all-targets -- -D warnings`, `cargo test --all-targets` and package checks before asking for review. No force-push, reset-hard or destructive cleanup is required by the build instructions.

## 日本語

統合ブランチは`master`です。可能であれば作業用ブランチを作成してください。Commit・Remote・認証・Releaseの既存の安全性を維持し、重要な仕様変更には回帰テストを追加してください。小さなファイルでも責任が異なる処理は独立モジュールへ分離します。コメントは英語・日本語の両方で、状態判定や安全性検査が必要な理由を具体的に説明し、形式的な定型コメントを避けます。レビュー前に`cargo fmt --all`、`cargo clippy --all-targets -- -D warnings`、`cargo test --all-targets`と配布テストを実施してください。ビルド手順にForce Push・Hard Reset・破壊的なクリーンアップは不要です。
